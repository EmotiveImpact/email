# Going live

How the platform runs in production, what it costs, and the steps that need your own accounts. Everything else is already in the repository: the image (`Dockerfile`), the AWS setup (`infra/`), and the deploy workflow (`.github/workflows/deploy.yml`).

## What runs where

| Piece | Where | Notes |
|---|---|---|
| Web app and API | ECS Fargate in London (eu-west-2), behind an HTTPS load balancer | One container serves both, so sign-in cookies stay on one address (D91) |
| Job worker | ECS Fargate, same image, `ROLE=worker` | Sends campaigns, runs flows every hour, retries webhooks |
| Database | Neon, AWS London region | The app uses the pooled address; migrations use the direct one (D94) |
| Email | Amazon SES, London | One SES tenant per business; delivery events come back by SNS (D96) |
| Pictures | S3 behind CloudFront | Private bucket; inboxes and the canvas load pictures through CloudFront (D100) |
| Secrets | AWS Secrets Manager | Neon addresses and Stripe and OpenAI keys; the two signing secrets are generated by AWS (D99) |

Expect about £90 a month whatever the number of customers: two small containers, the load balancer, public addresses and Neon. Email costs about 8p per 1,000 on top.

## Once only: the steps that need you

Do these in order. Anything in `<angle brackets>` is yours to fill in. The examples use `app.<yourdomain>` for the app and `mail.<yourdomain>` for the platform's own sending domain.

### 1. Neon (database)

1. In Neon, create a project in the **AWS Europe (London)** region, Postgres 17.
2. From Connect, copy two addresses: the **pooled** one (its host contains `-pooler`) and the **direct** one. Both should end in `?sslmode=require`.

### 2. AWS (first deploy from your computer)

You need the AWS CLI signed in as an administrator of the account, plus Node 22 and pnpm.

```sh
pnpm install
cd infra
pnpm exec cdk bootstrap aws://<account-id>/eu-west-2
pnpm exec cdk deploy EmailBase -c domain=app.<yourdomain>
```

If the account already has a GitHub sign-in provider (IAM, Identity providers, `token.actions.githubusercontent.com`), add `-c githubOidcProviderArn=<its ARN>`; an account can only have one.

This creates the image registry, the secrets and the role GitHub deploys with. Nothing is running yet and nothing costs much.

### 3. Put the database addresses in the secret

Save this as `secret.json` somewhere outside the repository, fill it in, then send it and delete the file:

```json
{
  "DATABASE_URL": "<pooled Neon address>",
  "DIRECT_DATABASE_URL": "<direct Neon address>",
  "STRIPE_SECRET_KEY": "",
  "STRIPE_WEBHOOK_SECRET": "",
  "OPENAI_API_KEY": "",
  "SQUARE_APP_ID": "",
  "SQUARE_APP_SECRET": "",
  "SQUARE_WEBHOOK_SIGNATURE_KEY": ""
}
```

```sh
aws secretsmanager put-secret-value --region eu-west-2 --secret-id email-platform/app --secret-string file://secret.json
rm secret.json
```

Empty Stripe keys mean plans cannot be changed yet, an empty OpenAI key means generated pictures are soft samples in the brand colours, and empty Square keys mean "Connect Square" shows as coming soon. All can be added later (steps 8 to 10). Keep every key in the file, even when empty: a container will not start if one is missing.

### 4. GitHub settings

In the repository: Settings, Environments, New environment, call it `production`.

- Add yourself under **Required reviewers**, so no deploy runs without your approval.
- Add these **variables** (not secrets; none of them are private):

| Variable | Example | Needed |
|---|---|---|
| `AWS_ACCOUNT_ID` | `123456789012` | Yes |
| `APP_DOMAIN` | `app.<yourdomain>` | Yes |
| `SENDING_DOMAIN` | `mail.<yourdomain>` | Yes, for real sending |
| `DEFAULT_FROM` | `<Product name> <hello@mail.<yourdomain>>` | Optional; defaults to `hello@` the sending domain |
| `CERTIFICATE_ARN` | an ACM certificate in eu-west-2 | Optional; without it the deploy asks ACM for one |
| `SES_SEND_RATE` | `14` | Optional; set it to the rate SES gives you in step 7 |
| `WEB_COUNT` | `1` | Optional; containers serving the app |
| `GITHUB_OIDC_PROVIDER_ARN` | | Only if you used it in step 2 |

### 5. First deploy

Actions, Deploy, Run workflow, branch `main`, then approve it.

On the first run the stack waits for the HTTPS certificate. In the AWS console (Certificate Manager, London) open the pending certificate and add the CNAME record it shows at your DNS provider. The deploy carries on by itself once ACM sees it, usually within half an hour.

### 6. DNS records

The deploy's summary (and CloudFormation, stack `EmailApp`, Outputs) lists every record. Add them at your DNS provider:

| Record | What for |
|---|---|
| `CNAME app.<yourdomain>` to the load balancer (`DnsApp`) | The app's address |
| Three `CNAME …._domainkey.mail.<yourdomain>` (`DnsDkim1` to `3`) | DKIM signing for the platform's own sending domain |
| `MX bounce.mail.<yourdomain>` and `TXT bounce.mail.<yourdomain>` (`DnsMailFromMx`, `DnsMailFromSpf`) | Bounces handled on our own subdomain, so SPF lines up with the From address |
| `TXT _dmarc.mail.<yourdomain>` (`DnsDmarc`) | DMARC, report-only to start |

When the app answers at `https://app.<yourdomain>/ready`, check the SES events subscription is confirmed (SNS, Topics, the `SesEvents` topic, Subscriptions). If it says "Pending confirmation" because DNS was not ready during the first deploy, ask SNS again; the app confirms it by itself:

```sh
aws sns subscribe --region eu-west-2 --topic-arn <SesEventsTopic output> --protocol https --notification-endpoint https://app.<yourdomain>/ses/events
```

### 7. SES production access

New SES accounts are in a sandbox: 200 emails a day, only to addresses you have verified. Ask AWS to lift it for London:

```sh
aws sesv2 put-account-details --region eu-west-2 \
  --production-access-enabled \
  --mail-type MARKETING \
  --website-url https://app.<yourdomain> \
  --contact-language EN \
  --additional-contact-email-addresses <you@yourdomain> \
  --use-case-description "<see below>"
```

A use case they tend to accept, to adapt:

> We run an email platform for UK appointment businesses (salons, clinics, studios). Each business sends booking confirmations and reminders to its own clients, and marketing only to clients who gave consent (recorded with source and time). Every marketing email has one-click unsubscribe (RFC 8058) and a postal address. Hard bounces and complaints are suppressed platform-wide through the account suppression list, and each business is a separate SES tenant whose sending pauses automatically if its bounce or complaint rate climbs. We expect about <N> emails a day at first.

AWS usually answers within a day. Once approved, set `SES_SEND_RATE` to the maximum send rate shown in the SES console and run Deploy again.

### 8. Stripe (when you want to take payments)

1. With the live secret key: `STRIPE_SECRET_KEY=<sk_live_…> pnpm --filter @platform/api stripe:setup`. This creates the five plans once.
2. In Stripe, Developers, Webhooks, add `https://app.<yourdomain>/billing/stripe` with the events `checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated` and `customer.subscription.deleted`. Copy its signing secret.
3. Turn on the customer portal (Settings, Billing, Customer portal) with plan changes and cancelling allowed.
4. Put both keys in the secret (as in step 3, with the database addresses kept), then run Deploy again. Secrets are read when containers start.

### 9. OpenAI (when you want real generated pictures)

Add `OPENAI_API_KEY` to the secret and run Deploy again. Each plan includes a monthly number of generated pictures (D98).

### 10. Square (when you want salons to connect their Square diary)

1. At [developer.squareup.com](https://developer.squareup.com/apps), create an application (for example "<Product> for salons"). In its OAuth page, choose Production and set the redirect URL to `https://app.<yourdomain>/connect/square/callback`. Copy the Application ID and Application secret.
2. In Webhooks, Subscriptions, add `https://app.<yourdomain>/connect/square/webhook` with the events `booking.created` and `booking.updated`, on API version 2024-10-17. Copy its signature key.
3. Put `SQUARE_APP_ID`, `SQUARE_APP_SECRET` and `SQUARE_WEBHOOK_SIGNATURE_KEY` in the secret (as in step 3) and run Deploy again.

Owners then connect from Settings, Booking system. The platform asks only for read access (D132). Without the webhook, diaries are still read every 15 minutes. To try it first, put the sandbox application's keys in the secret instead; the platform sees the `sandbox-` at the start of the id and talks to Square's sandbox.

### 11. Before the first real customer

- Sign up for Google Postmaster Tools for `mail.<yourdomain>` and each business domain that sends a lot. Gmail and Yahoo require SPF, DKIM and DMARC that line up, one-click unsubscribe, and a spam rate under 0.3%; the platform does the first three, and the reputation guard pauses a business before the last one hurts everyone.
- When DMARC reports look clean for a few weeks, move `_dmarc.mail.<yourdomain>` from `p=none` to `p=quarantine`.
- Turn on Neon's backups beyond the default if you need more than the plan's restore window.
- Decide who pays for each connected app. An app made with an account (sign-up, or Saleane and Caleane from the seed) pays for all its businesses on one bill. An app a customer adds in Developers bills each business on its own. To make an added app pay for its businesses instead, run `update apps set partner = true where id = '<app id>';` in Neon's SQL editor.

## Everyday

- **Deploy:** Actions, Deploy, Run workflow, pick the branch or commit, approve. Migrations run as the new version starts, under a lock, so two containers never run them at once.
- **Roll back:** a version that never gets healthy is rolled back automatically. To go back on purpose, run Deploy with the older commit; its image is already built.
- **Logs:** CloudWatch, the log group in stack `EmailApp`, streams `web/…` and `worker/…`. Kept for a month.
- **Change a secret:** update `email-platform/app`, then run Deploy (or `aws ecs update-service --force-new-deployment` on both services).
- **More capacity:** raise `WEB_COUNT`. The worker stays at one; pg-boss keeps jobs safe if it restarts.
- **Never** edit a migration that has run in production; add a new one.
